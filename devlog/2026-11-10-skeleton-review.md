# 工程骨架的五轮自审

这一轮要决定哪些约束应该写进公开接口，哪些应由后续适配器验证。[工程骨架设计](../design.md#工程骨架)

| 轮次 | 备选设计和取舍 | 验证 |
| --- | --- | --- |
| 1 · 构建边界 | 比较单体 App、四个独立包和一个本地核心包。四个接口目前都只用标准库或 Foundation，保留一个独立核心包即可单测和替换实现。App 与包统一用 Swift 6，让日常构建也检查并发约束。 | 切换后独立包测试通过。 |
| 2 · 原生选区 | 比较 Foundation 范围转换、NSRange 往返校验和逐端字符边界校验。保留逐端校验。 | 枚举 11 段文本的 368 个区间，前两种各误放行 147 个，逐端校验与字符边界一致。组合音标和 CRLF 的反例已加入 XCTest。 |
| 3 · 异步改稿 | 比较一批带段落 ID 的请求与逐段请求。保留逐段接口，调用方在等待前固定送审稿及选区，收齐替换后一次提交。这样模型无需返回位置或识别重复段落。 | 包外调用样例将两个相同段落分别送审，挂起恢复后得到两个不同位置的替换。基于送审版本调用 apply 的代码通过编译。 |
| 4 · Diff | 比较偏移补丁与有序文本分段。保留分段，明确两侧可拼回各自原始 UTF-8，并让比较器可安全传入后台任务。 | 后台调用方在修订前编译失败，加入 Sendable 后通过。用预组合和分解形式的 é 验证分段可还原两侧原始字节，两种写法的 UTF-16 长度不同。 |
| 5 · 存储 | 比较调用方分别取快照、Markdown 和 ID，与文档一次生成归档。采用后者。每篇文章由一个会话顺序保存，适配器负责整份提交。 | 并发样例复现旧保存晚完成、覆盖新稿。改为依序等待后，内存存储样例的快照和导出都对应最后一稿。子 Agent 已复核归档接口及失败语义。 |

从仅含待提交文件的干净副本运行 `make lint`、`make test`、`make build`，风格检查、3 项 XCTest 和 macOS App 构建均通过。

运行样例使用测试替身。真实 Diff 算法、模型响应、Loro 恢复和磁盘写入中断均留到相应适配器实现时验证。
