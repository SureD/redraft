# 交互原型：完整改稿循环

- **缘由**　原生应用动工之前，需要一个能实际操作的原型，验证改稿循环的交互是否顺手：写作时怎样标记段落，审阅时怎样对照送审稿逐处取舍，回看时怎样找到一句话的来历。原型只用于设计验证，不替代 macOS 应用。
- **改动**　新增 [`prototype/`](../prototype/README.md)：纯 HTML、CSS、JavaScript，打包成一个可离线打开的单文件。覆盖写作、标记、模拟改稿、审阅取舍、生成定稿、版本对比、逐句溯源、改写范例和撤销。Diff 在浏览器里实时计算，分层方式与[技术设计](../design.md)一致；AI 改稿由本地模拟，并在界面上如实标注。理念与设计决策的对应、演示与真实功能的边界写在原型的 README 里。
- **验证**　用 Playwright 驱动 Chrome 跑完核心流程和编辑器细节，共 30 多项检查全部通过，包括输入法组字期间不同步、确认上屏后同步并可撤销，分段、合并、多行粘贴、键盘和拖动移动段落、取舍的撤销与重做、生成定稿后撤销、刷新后数据保留。在 1440、1024、390 像素宽度和深色模式下截图检查布局，并确认减少动态效果偏好会关闭过渡和动画。
- **遗留**　浏览器的分词结果与 NLTokenizer 不完全相同，原生实现时需要用同一批示例重新核对 Diff 的可读性。修改的分组目前在两处修改只隔一两个字时合并，个别中文句子仍会出现“删一大段、补一大段”的情况，值得在原生 Diff 引擎里继续调。
