# 交互原型：图片与表格

- **缘由**　用户确认在纸面配色的原型上加入图片和表格，要求能插入、编辑、参与审阅，与现有的编辑、审阅、历史自然融合，不重做布局和视觉。图片按整张处理；表格单元格文字走文字 Diff，增删行列单独确认。不做公式、合并单元格和链接。
- **数据**　图片和表格是正文里的块，和段落一样有稳定 ID。图片块 `{kind: 'img', text: 图注, img: {asset, w, alt, iw, ih}}`，表格块 `{kind: 'table', text, table: {cols: [列 ID], rows: [{id, cells}], head}}`；行和列都有自己的 ID，结构修改才能按身份对齐，而不是按位置猜。块的 `text` 是派生的纯文本（图注；单元格用制表符和换行拼接），所以字数、搜索、旧的文字路径不需要改。图片数据按资源 ID 单独存在 `redraft.asset.<id>`，文章里只存引用，避免每次保存都重写整张图；启动时清掉没有任何文章或版本引用的资源。存储版本升到 5，旧数据原样迁移并补上新示例。
- **Diff**　段落层面块和段落一样按 ID 对齐。图片比较资源 ID，不同就是一处“替换”；图注是一组文字修改。表格先按行 ID、列 ID 合并顺序，得到新增和删去的行列，每条是一处结构修改；双方都有的格子各自是一组文字修改。审阅键沿用 `段落:序号` 的格式，扩展出 `段落:行.列:序号`、`段落:row:ID`、`段落:col:ID`、`段落:img`。定稿合成先定结构，再在保留下来的格子里套用文字取舍。来历按单元格查找，记录里带上格子位置。
- **编辑器**　块在 contenteditable 正文里是不可编辑的岛，图注和单元格用自动增高的 textarea，输入法和撤销都走原生控件，变更同步回模型并合并成一步撤销。光标在段落边缘按方向键进入相邻的块，`Backspace`/`Delete` 先选中块再删除，删除时提示条带撤销。行列操作先在副本上试做，失败时不留撤销记录。粘贴和拖入图片走同一条导入路径，文件类型、大小、解码失败、存储已满都有一句话的提示，失败不改动文档。
- **模拟 AI**　仍然完全本地。示例图片和示例表格有预置改法（换图、删列、加行），说明里写明“模拟 AI 不识别图片内容”；其他块只对图注和单元格文字套用本地精简规则。
- **导出**　HTML 用 `figure`/`table` 保留全部内容，图片内嵌；自己复制粘贴时用 `data-rd-*` 属性还原块。Markdown 用 data URL 图片加斜体图注，表格写成 GFM，`|` 转义、换行写 `<br>`；显示大小只在 HTML 里保留。
- **验证**　Node 里 25 项模型测试（预置、结构 hunk、定稿、历史、单元格来历、导出、损坏数据回退）。Chrome 无头实测图片与表格编辑 41 项、混合审阅 24 项、回归与迁移 20 项，深色和 390 px 窄屏各跑一遍审阅流程，全部通过且没有页面报错。实测中修了三处：采用换图后图片按原始宽度撑出横向滚动；换图和列修改的操作条盖住了图注和本列的格子，改为放在整张图或整张表下方；行列获得焦点时的蓝底盖住了增删底色，改成叠加浅蓝加描边。
- **遗留**　没有在 Safari、Firefox、移动浏览器上实测；单元格里的中文输入法组字、触屏拖放、屏幕阅读器、接近存储上限的大照片都还没覆盖。原生应用里图片应放进文档包，表格对应 TextKit 2 的附件视图，待架构落地时再定。
