# 统一文档模型与状态归属

本次按[技术设计](../design.md)收拢原生 UI 展示模型与 Core 纯文本稿件之间的分歧。文章、结构化内容块、语义富文本、版本与审阅类型统一放入 RedraftCore；`ArticleSession` 是当前文档的唯一修改入口，校验块、表格、UTF-16 范围和版本身份，并拥有改稿请求的取消与过期结果隔离。相同 revision 必须对应同一份规范化文档，历史快照不随当前正文修改。

`WorkspaceStore` 只拥有会话集合与改写范例，`WorkspaceViewModel` 从会话计算只读展示数据，`WorkspaceState` 仅保留窗口交互状态。共享 Store 的多个 ViewModel 能同时观察正文与审阅更新，同时保留独立的窗口状态；其他窗口删除文章、删块、缩短文本或结束审阅后，会修正失效选区并关闭相应弹窗。

文章源、改稿服务与示例图片从应用入口显式注入，演示实现集中到 `App/Preview`；空来源不会偷偷载入示例。原生富文本通过桥接转换为 Core 语义数据，标题不再由字号推断，全局当前编辑器被窗口级 `EditorSession` 替代。组字保留在原生缓冲，提交时检查基准内容，避免旧输入覆盖其他位置的新修改。图片选择与解码留在原生适配器。

验证：Core 16 项 XCTest、工作区 12 组场景、编辑器 12 组场景通过；完整 macOS App 构建与严格格式检查通过。10 张真实原生视图快照完成，检查了深浅色、窄窗口、TextKit 2 和 NSVisualEffectView，并目视核对写作、日记排版与紧凑审阅界面。测试构建已链接实际 Core 模块，不再只编译 App 的独立展示模型。

当前仍是 UI 与内存会话实现。真实 AI、磁盘保存、Loro、词级 Diff 与审阅定稿合成继续留空；预览审阅完成只记录取舍。原生撤销仍按文本块输入会话管理，跨块选区与文章级统一撤销未实现。
