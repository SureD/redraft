# 用 macOS 26 的 TextEditor 写正文

作者确认 Redraft 可以面向 macOS 26。新稿、已有文章、图表前后的正文都使用 SwiftUI 富文本 `TextEditor(text:selection:)`。原来的每块 `NSTextView`、插入点绘制和逐视图撤销栈已移除。图片、图注和可编辑表格仍使用各自的控件。[前次选型](2026-11-22-writing-editor-survey.md) · [Apple 的富文本编辑示例](https://developer.apple.com/videos/play/wwdc2025/280/)

连续的文字块进入同一个编辑器。旧块之间的换行保留下一个块的 UUID，用户在一个块内按回车仍可写多个自然段。跨块删除和撤销一起作用于文本及边界，Core 以一次提交更新正文。这样，一篇旧稿在录入、批注、成稿三个阶段能认回同一段。跨图片、表格的选择和整篇文档撤销仍有独立控件的边界。

系统输入法可能将预编辑的拼音送入富文本绑定。编辑器缓冲保留候选内容，确认后再提交给文章会话。提交时校验文章和文字块的基准内容，防止一个窗口的旧输入覆盖另一个窗口的修改。批注期间原稿保持只读。

字符样式、行高和选区跟随系统富文本控件。原稿的列表、精确缩进和两端对齐通过 TextKit 的布局段落显示。编号绘制在正文旁，复制、搜索及批注继续使用原有字符坐标。编辑器按实际行框给稿纸留出高度，窗口变窄时末行仍完整显示在下一张图之前。

## 验证

App 和可执行文件的最低系统版本均为 26.0，在 macOS 27.2.1 使用 Xcode 27.2 构建。20 项 Core 测试、16 组工作区场景和 14 组编辑交互通过。真实窗口覆盖新稿首字、跨三块替换和撤销重做、段落标记恢复、中文组字期间的外部修改、长文光标跟随，以及格式撤销。11 张原生窗口快照覆盖图文表稿件、批注阅读、成稿轨迹和宽窄窗口。软换行回归检查《阳台的一年》首段最后一个句号的字符框是否完整可见。

真实窗口测试通过系统输入接口模拟组字，手动操作拼音候选窗与 macOS 26.0 实机仍待复验。测试进程无法向命名系统粘贴板写入图片，故跳过该项实机粘贴，保留图片导入和纯图片识别测试。当前环境的 LaunchServices 在注册独立应用进程时中止，窗口测试从编译后的写作视图和工作区视图启动。
