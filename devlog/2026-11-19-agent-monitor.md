# 需求运行看板

为让工程师看到各模块的工作进展和需要参与的架构决定，在现有架构页增加了本地运行看板入口。每条需求记录目标、分工、等待条件和整体验收。模块链接沿用架构清单的 ID。桌面聊天里的工作由 Agent 上报，从看板命令启动的进程另有启停和心跳记录。具体约定见[开发流程](../devflow.md)与[使用说明](../README.md#需求运行看板)。

本次搭建作为首条真实需求登记，含环境调研、状态记录、界面和集成四项分工。在浏览器里从架构页进入看板，展开任务核对了分工和上报来源。使用临时记录验证了决策和等待状态、窄屏布局、刷新时保留选中项，以及断线恢复。通过看板运行了 7 项回归测试，覆盖并发写入、子进程正常退出与失败、信号中断、失去心跳后重试、延迟回调和显式验收。测试正常退出时，需求仍处于整体验收阶段。
