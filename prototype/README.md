# Redraft 交互原型

这是 Redraft 的网页交互原型，用来体验[产品想法](../idea.md)里的完整改稿循环：先专心写作，再标记段落请 AI 改稿，然后对照送审稿逐处取舍，每一轮都留在历史里，可以回看一句话的来历，也能把取舍积累成自己的写作范例。正式产品按[技术设计](../design.md)做原生 macOS 应用，这个原型不替代它。

## 怎样查看

- **直接打开**：用浏览器打开 [`dist/redraft-prototype.html`](dist/redraft-prototype.html)。这是一个单文件，样式和脚本都内联在里面，离线可用，不需要账号、密钥或网络。建议用最新版 Chrome、Edge 或 Safari 打开。
- **从源码运行**：`src/index.html` 也可以直接打开；或者在仓库根目录运行 `python3 -m http.server 8000`，再访问 `http://localhost:8000/prototype/src/`。
- **重新打包**：修改 `src/` 之后运行 `node prototype/build.mjs`，会重新生成 `dist/redraft-prototype.html`。不需要安装依赖。

内容保存在浏览器的本地存储里。想回到初始状态，在窗口工具栏右上角的“更多”菜单里选“恢复示例数据”。显示设置单独保存，不随示例数据重置。

## 建议的体验路线

1. 打开后是《雨季的旧书店》。它已经完成过一轮改稿，作者又续写了两段，并标记好了要求（更简洁、更具体）。
2. 在任意段落里写几个字、回车分段。常用操作都在窗口顶部的编辑工具栏上：撤销、重做，上移、下移段落，存为版本。也可以用快捷键：`Alt+Shift+↑/↓`（Mac 上是 `⌥⇧↑/↓`）移动段落，`Ctrl/⌘+Z` 撤销；或者拖动段落左侧的手柄。
3. 把光标放进一段，点工具栏的“标记”（`Ctrl/⌘+Shift+M`），再从旁边的“修改要求”里选怎样改；选中几段时会一起标记。段落左侧的圆点和段落下方的标签做同样的事，可以在工具栏的 `Aa` 里关掉左侧控件。
4. 点工具栏右端的 `Aa` 调整字体、字号、行距、栏宽，或打开“专注当前段落”。这些设置只影响显示，不改动正文。
5. 点“请 AI 改稿”（`Ctrl/⌘+Enter`）。模拟改稿期间编辑工具栏上的编辑类按钮会变为不可用，悬停可以看到原因；改完后自动进入审阅。
6. 在审阅里用 `J`/`K` 在修改之间移动，`A` 采用改法、`O` 保留原句、`E` 自己重写；也可以直接点修改处，用浮出的操作条。右侧检查器同时给出原句、改句和这处修改的说明。可以切换“行内”和“上下对照”两种读法。
7. 点“完成本轮”生成定稿。未决定的修改会询问怎样处理；生成后仍可撤销。
8. 在“写作”里把光标放进某一句，点工具栏的“来历”（`Ctrl/⌘+I`），沿时间线读到初稿写法、AI 改稿和自己的取舍。
9. 切到“历史”，任选两稿对照，或点时间线上的一稿与它的上一稿对照。
10. 在左侧打开“改写范例”，按取舍或问题类型筛选，点“在文章中查看来历”回到原文。
11. 《给新同事的一封信》是一篇改稿已返回、待审阅的文章，可以直接练习审阅；《Keeping a Notebook》演示英文和没有历史的空状态；“新建文章”演示空白文章。

## 产品理念与设计决策

| 理念（来源） | 原型中的设计 |
| --- | --- |
| 写初稿时专心把话写下来，选词、挪动段落、撤销都顺手（idea.md） | 正文是不透明的安静纸面，界面框架才用半透明材质。回车分段、粘贴多行、拖动或用快捷键移动段落、撤销与重做都由同一套段落模型处理，输入法组字期间不同步，确认上屏后再写入。 |
| 常用操作要一眼找到，习惯常驻工具栏的作者不必去找悬停控件（用户反馈） | 写作时在窗口工具栏下方常驻一条编辑工具栏，正文从它下面滚过，任何时候都能点到。按用途分组：撤销与重做；标记与修改要求（一个分体按钮）；上移与下移段落；存为版本与这句话的来历；右端是状态和 `Aa` 显示设置。按下按钮不夺走正文焦点，光标和跨段选区原样保留，可以接着打字；菜单、对话框关闭后光标回到原处。段落左侧的悬停控件保留为直接操作的捷径，可以关闭。 |
| 正文是纯文本段落，Diff 和溯源都建立在文字上（design.md） | 工具栏不放粗体、标题、列表等格式按钮。这些在当前模型里没有对应，加上只会是摆设，或者让“只改了格式”的版本在对比和溯源里无从表达。字体、字号、行距、栏宽、专注模式只是显示偏好，存在本机，不进入文档和版本。 |
| 自己改过一轮后，再标出想请 AI 修改的段落（idea.md） | 标记是段落级的：一个圆点开关，加一个要求标签（更简洁、更具体、更顺口、语气更自然或自定义）。标记段落变成淡色卡片，检查器集中列出所有标记，送审前一目了然。 |
| AI 按标记改稿，每完成一次就生成一个新版本（idea.md、design.md 的文章会话） | 送审时保存“送审稿”快照，AI 改完保存“AI 改稿”版本，作者取舍后生成“定稿”。改稿期间正文锁定并显示进度，可以取消。 |
| 对照送审稿读改动，决定保留原句、采用改法，或自己再写一遍（idea.md） | 审阅视图按文章顺序呈现，未标记段落作为浅色上下文保留。每处修改都可以单独保留、采用或重写，并配有改动说明；检查器把完整的原句和改句并排给出。决定后自动跳到下一处未决定的修改。 |
| Diff 按阅读顺序呈现，保留上下文；只改一个标点也能看清（design.md） | 段落按稳定 ID 对齐，再按词比较。中文用系统分词，避免把一个词拆碎；两处修改之间只隔一两个字时合并为一处，读起来是完整的改动。删除用删除线加底色，新增用下划线加底色，不只靠颜色区分。 |
| 每一轮都留在历史里，回看定稿中的一句话能找到初稿写法、AI 改稿和自己的取舍（idea.md、design.md） | “历史”可以任选两稿对比，并标出新增、删去和移动的段落。“这句话的来历”从当前稿出发，在同一段落的各稿中逐级找到这句话，列出每一稿的变化，并在定稿那一步写明你采用、保留或重写了什么。 |
| 改过的句子就是自己的写作范例（idea.md） | 每次完成审阅，每一处取舍都会记入“改写范例”，带原句、AI 建议、最终写法、说明和问题类型，可以筛选和搜索，并能跳回原文看来历。 |
| 本地优先，AI 服务可替换，Mock 使用相同接口（design.md） | 内容保存在本机浏览器。AI 改稿完全由本地模拟，接口形态与设计中的改稿服务一致：输入标记段落和要求，返回改写文本和逐处说明。 |

## 界面结构

- **文章库**（左侧半透明材质）：文章列表、搜索、待审阅和改稿中的状态标记、改写范例入口、新建文章。窄屏时变为抽屉。
- **窗口工具栏**（半透明，正文从下方滚过）：文章标题和保存状态，“写作 / 审阅 / 历史”分段控件，主操作（请 AI 改稿、继续审阅或完成本轮），更多菜单和检查器开关。
- **编辑工具栏**（只在写作时出现，与窗口工具栏同一种材质，用细线分开）：撤销、重做｜标记、修改要求｜上移、下移段落｜存为版本、来历｜状态（第几段、已标记几段，或“正文已锁定”）、`Aa` 显示设置。每个按钮都有工具提示，写明名称、快捷键，不可用时写明原因。宽度不够时先收起状态和文字标签，再把移动段落和来历收进“更多编辑操作”菜单，撤销、标记、修改要求、存为版本和显示设置始终留在栏上。审阅和历史有各自的工具，不显示这条工具栏。
- **正文**：不透明纸面，默认阅读宽度约 38 个字，正文 17 px，行高 1.9，可以在 `Aa` 里调整。
- **检查器**（右侧半透明材质）：随视图变化。写作时是“改稿标记”和“这句话的来历”；审阅时是进度、当前修改的原句和改句、说明和操作；历史时是版本时间线。宽度不足时浮在正文之上，窄屏时成为底部面板。
- **浮层**：操作条、弹出菜单、对话框和提示条都使用较厚的材质和阴影，层级高于界面框架。

## 状态

- 文章：空白文章、正在写作、改稿中、待审阅、已完成若干轮、没有任何版本。
- 标记：无标记、已标记（带要求）、改稿中（等待、改稿中、已改完）。
- 审阅：每处修改的未决定、采用、保留、重写；AI 没有修改某一段；全部决定后完成；有未决定项时完成会询问。
- 历史：没有版本、两稿相同、有改动（新增、删去、移动段落，折叠未改动段落）。
- 来历：光标不在正文、这句话还没有经过改稿、有完整演变。
- 范例：还没有范例、筛选后为空。
- 撤销：编辑、标记、修改要求、移动段落、送审、审阅中的每次取舍、生成定稿、存为版本都可以撤销；删除文章通过提示条撤销。工具栏上的撤销、重做按钮会写出下一步撤销的是什么（例如“撤销移动段落”），没有可撤销的操作时不可用。
- 编辑工具栏：光标不在正文（例如在标题里）时，段落操作不可用；选中多段时“标记”变为“标记 N 段”，移动不可用；第一段不能上移、最后一段不能下移；改稿中，编辑、撤销、存为版本都不可用；待审阅时正文仍锁定，但可以撤销送审；显示设置和来历始终可用。

## 键盘、可访问性与偏好

- 所有主要操作都有键盘路径，`Ctrl/⌘+/` 显示快捷键表。审阅里只有当前修改处在 Tab 序列中，用 `J`/`K` 移动，避免几十个 Tab 停留点。
- 焦点环清晰可见；对话框有焦点陷阱，`Esc` 关闭并把焦点还给原来的控件；菜单支持方向键。
- 编辑工具栏是一个 `role="toolbar"`，只占一个 Tab 停留点：`Alt+F10`（Mac 上是 `⌥F10`）从正文跳到工具栏，`←`/`→` 在按钮间移动，`↓` 打开菜单，`Esc` 回到正文里原来的光标处。不可用的按钮仍可聚焦，朗读时会读出原因。
- 每处修改有完整的朗读标签（例如“修改 3：把‘随便’改为‘随手’。已采用改法”），重要变化通过朗读区域播报。
- 跟随系统的深色模式；`prefers-reduced-motion` 时关闭过渡和动画；`prefers-reduced-transparency` 时材质变为不透明；高对比度模式下删除线和下划线仍然区分修改。
- 支持宽桌面、中等宽度和手机宽度。

## 演示与真实功能的边界

**真实运行**：段落编辑和同步、输入法组字保护、分段、多行粘贴、段落拖动与快捷键移动、编辑工具栏上的全部按钮和显示设置、撤销与重做、标记和要求、送审与取消、版本快照、逐处取舍与定稿合成、任意两稿对比、逐句溯源、改写范例、Markdown 导出、本地存储。Diff 在浏览器里实时计算，不是预先画好的效果。

**模拟**：AI 改稿。示例段落使用预置改法和说明，因此能看到完整的改稿效果；你新写或改动过的段落只做删赘词等少量确定的本地规则精简，没有可改之处时会如实显示“没有修改”。自定义要求会被记录，但模拟服务不会理解它。整个原型没有网络请求，也没有后端。

**没有做**：富文本格式（有意不做，见上面的设计决策）、段落样式、真实模型接入与密钥管理、多设备同步、原生 macOS 的系统能力（拼写检查、Writing Tools、服务菜单等）。这些属于正式应用的工作。衬线字体在 macOS 上使用宋体；系统里没有中文衬线字体时，中文会退回默认字体，英文仍是衬线。

## 与技术设计的对应

| 原型文件 | 对应 design.md 中的模块 |
| --- | --- |
| `src/diff.js` | 文本对比：段落按 ID 对齐，`Intl.Segmenter` 分词（对应 NLTokenizer），词元 LCS（对应 `difference(from:)`），短间隔合并（对应语义清理）。 |
| `src/session.js` | 文章会话、文档与版本：送审、生成 AI 版本、取舍合成定稿、逐句溯源、取舍记录。段落 ID 代替 Loro Cursor 提供稳定身份，每一稿保存完整快照。 |
| `src/mock-ai.js` | AI 改稿服务的 Mock：输入标记段落和要求，返回改写文本和说明。 |
| `src/app.js`、`src/styles.css` | 编辑界面与本地文章库。 |
| `src/samples.js` | 示例文章。第 1 轮历史通过同一套会话流程生成，数据结构与真实操作一致。 |
